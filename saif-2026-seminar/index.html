에이전트의 작업 반복

목표를 이해하고, 도구로 시도하고, 결과를 확인한 뒤 다음 행동을 고른다.

  1. 목표와 완료 조건

    사람이 문제, 사용할 자료·도구, 허용 범위, 성공을 판단할 기준을 정한다.

  2. 실행과 관찰

    에이전트가 여러 단계를 수행하고 중간 결과를 읽는다. 오류나 부족한 점이 있으면 계획을 바꾼다.

  3. 검증과 인수

    테스트나 측정으로 결과를 확인한다. 중요한 결정은 사람에게 넘기고 승인된 결과물을 남긴다.

성과의 단위는 확인된 결과물

실행량이 늘수록 좋은 문제를 고르고 결과를 검토하는 일이 더 중요해진다.

  • 활동을 보여주는 지표

    토큰 사용량, 실행 시간, 생성한 코드·문서의 양. 얼마나 많이 시도했는지 설명하는 데 도움이 된다.

  • 완료를 보여주는 증거

    통과한 테스트, 수용된 문서, 재현 가능한 실험 결과, 실제 문제 해결. 업무 목적에 맞는 별도 확인이 필요하다.

  • 사람에게 남는 병목

    질문과 실험 설계, 입력 준비, 장비 접근, 결과 검토, 다음 우선순위 결정.

  • 실행마다 필요한 경계

    가치 있는 질문, 멈출 조건, 나중에 확인할 기록. 오래 실행했다는 사실만으로 업무 가치가 정해지지 않는다.

권한과 승인은 시스템이 집행한다

에이전트에게 주의사항을 말하는 것과 실제 행동을 제한하는 것은 서로 다른 설계 요소다.

  • 누구의 권한인가

    사용자 신원을 확인하고 허용된 데이터와 도구에만 접근하게 한다.

  • 어떤 행동까지 가능한가

    승인된 행동 목록을 두고, 위험이 큰 행동은 사람이 승인하도록 연결한다.

  • 어떤 비용까지 가능한가

    팀별 예산·모델 목록·사용량 제한을 에이전트 밖의 실행 경로에 둔다.

  • 문제가 생기면 무엇을 볼 수 있나

    활동 기록과 비용을 남겨 점검하고, 중단하거나 원인을 찾을 수 있게 한다.

한 번의 답변 가격과 업무 총비용

여러 단계가 연결된 일에서는 재시도와 실패가 최종 품질과 비용을 바꾼다.

단계가 쌓이는 예

각 단계가 95% 확률로 성공하고 열 단계가 모두 성공해야 한다고 가정하면, 전체 성공 확률은 약 60%다.

95%를 열 번 곱한 설명용 계산이다. 각 단계가 독립이라는 가정이 있으며, 실제 에이전트의 공통 성공률을 뜻하지 않는다.

비교할 단위

  • 해결한 문의 한 건의 비용

    추론 비용, 도구 사용, 재시도와 사람의 확인 시간을 합쳐 본다.

  • 품질을 통과한 기능 한 개

    생성 코드의 양보다 테스트와 검토를 거쳐 실제로 받아들인 결과를 센다.
